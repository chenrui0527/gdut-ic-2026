# 复现用的六个设计分别是什么

论文表 III 里用的六个基准设计来自 VTR（Verilog-to-Routing）仓库的 `vtr_flow/benchmarks/fpu/softlogic/`，
作者把它们转成了 BLIF（`bfly.abc.blif` 这种）。作者仓库的 `Benchmarks/README.md` 里写明了这个来源。

## 一、逐个是什么

依据是作者仓库 `Benchmarks/Verilog/<名字>.v` 里被注释掉的 `//assign` 那几行（那是这个设计的原始算式）。

| 名字 | 是什么 | 源码依据 |
|---|---|---|
| **bfly** | **FFT 蝶形运算单元**（butterfly）。注意：不是完整的傅里叶变换 | `re_z = (re_x·re_w − im_x·im_w) + re_y`；`im_z = (re_x·im_w + im_x·re_w) + im_y` —— 就是复数乘法 z = x·w 再加 y，正是 FFT 里的一步蝶形运算 |
| **dscg** | 一个二维旋转迭代单元，从算式看像**数字正余弦发生器**那一类（名字的官方解释我没查到） | `s1_out = (cos+1)·s2 + cos·s1`；`s2_out = (1−cos)·s1 + cos·s2` |
| **fir** | **FIR 滤波器**（有限冲激响应滤波器） | `out = k0·x + k1·x[n−1] + k2·x[n−2] + k3·x[n−3]`，4 个抽头系数 k0~k3 |
| **ode** | **常微分方程的数值积分单元**（欧拉法） | `y_pi_out = y_pi + h·half·(t_pi − y_pi)`，时间每次往前推 `h` —— 就是在解 dy/dt = t − y |
| **or1200** | **OpenRISC 1200 处理器**，一个完整的开源 RISC CPU 核 | 5236 行 Verilog；端口全是 Wishbone 总线（`icpu_dat_i`、`icpu_adr_i`、`icpu_ack_i`…）。VTR 官方文档里 or1200 那一行写的就是 "Soft Processor" |
| **syn2** | **人工合成的测试电路**，不对应任何真实功能模块 | `in1`~`in5` 混着加减乘，看不出任何功能 |

## 二、论文表 III 给的规格

| 设计 | I/O 引脚 | 节点数（AIG 与门数） | 触发器 | 层数（网表深度） |
|---|---|---|---|---|
| bfly | 482/257 | 28910 | 1748 | 97 |
| dscg | 418/257 | 28252 | 1618 | 92 |
| fir | 450/225 | 27704 | 1882 | 94 |
| ode | 275/169 | 16069 | 1316 | 98 |
| or1200 | 588/509 | 12833 | 670 | 148 |
| syn2 | 450/321 | 30003 | 1512 | 93 |

（"482/257" 是输入/输出引脚数。节点数最小的是 or1200，但它的层数最大——因为它是处理器，控制逻辑链特别长。）

## 三、几个容易被问住的点

1. **bfly 不是"完整的傅里叶变换"**，是 FFT 里的蝶形运算单元。这是最容易说错的一个。
2. 除了 or1200，其余五个都是拿 **32 位浮点加法器和乘法器**（源码里的 `fpu_add`、`fpu_mul` 模块）搭出来的——因为它们来自 VTR 的 **fpu（浮点单元）** 目录。
3. **syn2 是"合成"出来的**（synthetic），不是某个真实电路，所以它没有"这电路是干什么的"这种答案。
4. **or1200 是唯一的真处理器**，也是网表最深的（148 层）。这也解释了它为什么在我们复现里总是那个"例外"——论文里它在 VTR flow 下也几乎没有改善。
5. **dscg 我没有找到官方解释**，表里那一栏是我从算式反推的。如果被追问，就照实说："代码里在做二维旋转迭代，名字的具体展开我没找到官方说明。"

## 四、你自己怎么核对

打开作者仓库 [Yu-Maryland/FlowTune](https://github.com/Yu-Maryland/FlowTune) 里 `Benchmarks/Verilog/` 目录下的 `<名字>.v`，
文件里被注释掉的 `//assign` 那几行就是这个设计的原始算式，一眼能看出来。
